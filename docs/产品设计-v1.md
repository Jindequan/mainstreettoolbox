# Main Street Toolbox — 产品设计文档 v1

> mainstreettoolbox.com · "Free tools for Main Street, not Wall Street."
> 面向美国基层小微商户（餐饮/保洁/草坪/装修/美甲/零售）的免费在线工具箱。
> 本文档只管：页面、交互、业务流程。视觉风格另行设计（见 前端规范-v1.md）。

## 1. 产品定位

**一句话**：美国小微商户的免费计算器与工具集合——算得快、看得懂、结果带得走。

**不是什么**（同样重要）：
- 不是 Canva 类设计工具（避开 5/5 难度红海）
- 不是 AI 生成器门户（避开 ChatGPT 直接替代）
- 不是 SaaS 管理系统（是 Jobber/Toast 的**上游漏斗**，不是竞品）

**变现三轨**（上线起就按此设计，先不接广告）：
1. Affiliate：Toast（$1,250/单）、TouchBistro（至 $1,000）、Gusto（$200-300）、Homebase（$80+）
2. Pro 订阅：$9/mo 或 $79/yr（存档/客户管理/报告导出）
3. （远期）广告——账号解除警告前**禁止**接入

**用户画像**（所有交互决策对着这两个人做）：
- **Pam，48 岁**，经营 40 座小餐馆，不用 Excel，用手机搜索 "tip out calculator"。耐心 10 秒，看不懂行话。
- **Dana，29 岁**，一个人做 cleaning business，在客户家里**用手机现场**算报价、当场打印/展示给客户看。

**由此推出的三条设计铁律**：
1. **移动优先**——预计 65-75% 流量来自手机。一切交互单手可完成。
2. **零门槛**——进页即用，无注册、无教程、无"提交等待"。所有输入预填行业典型值，用户只改数字。
3. **结果带得走**——每个结果都有 Save / Email / Print / Copy link 四个动作。这是邮箱捕获、回访、付费转化的全部钩子。

## 3. 核心页面设计

### 3.1 工具页通用模板（★★★ 全站最重要的页面，其余都是变体）

**职责**：既是交互工具，又是 SEO landing page。每个工具页 = Above the fold 能干活，Below the fold 能排名。

**桌面布局**（两栏）：
```
┌──────────────────────────────────────────────────────┐
│ Home / Restaurant / Tip Out Calculator   [LOGO] [Pricing]│  ← 面包屑+导航
├──────────────────────────────────────────────────────┤
│ Tip Out Calculator                        ← H1=关键词   │
│ Split tips fairly in 30 seconds. No signup.           │  ← 副标题带承诺
├───────────────────────────┬──────────────────────────┤
│ 输入区 (58%)               │ 结果卡 (42%, sticky)      │
│ ┌ Tips this period         │ ┌────────────────────┐  │
│ │  [$ 847.50        ]      │ │  Per server: $118.65 │  │  ← 大数字
│ │  Total tips              │ │────────────────────│  │
│ │ Roles & split            │ │ ██████|▒▒▒▒▒▒▒|    │  │  ← 基准标尺
│ │  Servers   70% (3 ppl)   │ │  industry  │ you   │  │
│ │  Bussers   20% (2 ppl)   │ │────────────────────│  │
│ │  Bar       10% (1 ppl)   │ │ ✓ Balanced split    │  │  ← 一句话诊断
│ │ ▸ Show advanced options  │ │ [Save][Email][Print]│  │  ← 动作条
│ │   (rounding, hourly…)    │ │ [Copy link]         │  │
│ └ …                        │ └────────────────────┘  │
├───────────────────────────┴──────────────────────────┤
│ What this number means      ← 结果解读，人话翻译 3-5 句 │
│ Next steps                  ← 变现位（按诊断结果路由） │
│ FAQ (schema)  ·  Related tools (同行业互链 4-6 个)     │
└──────────────────────────────────────────────────────┘
```

**移动布局**（垂直流 + sticky 结果条）：
输入区在上；**底部 sticky 结果摘要条**（大数字+状态色，高 64px，随输入实时更新）；tap 摘要条展开完整结果卡（全屏 sheet，带 Save/Email/Print）。输入完任一字段后自动滚动露出摘要条。键盘弹出时摘要条贴在键盘上方。

**交互规格**（逐条验收）：

| # | 交互 | 规格 |
|---|------|------|
| 1 | **实时计算** | `input` 事件 → 150ms debounce → 重算。**全站不存在"计算/提交"按钮**（配方的 add ingredient 行除外）。结果更新用 `aria-live="polite"` |
| 2 | **预填典型值** | 所有字段带行业默认值（tip out 默认 70/20/10；food cost 目标默认 30%）。默认值旁标注 "typical"。附 "Reset to typical" 文字链 |
| 3 | **数字键盘** | 全部金额/数量输入 `inputmode="decimal"`，iOS/Android 弹数字键盘；`type="text"` + 自校验（避免 `type=number` 的滚轮误触和千分位问题） |
| 4 | **比例类用滑杆** | 百分比目标（food cost 20-35%）用滑杆+数字框双向联动，步长 0.5 |
| 5 | **高级选项折叠** | 必填输入 ≤5 个；其余进 `▸ Show advanced options`（styled details），默认收起。折叠状态不影响计算（高级项也有合理默认值） |
| 6 | **基准标尺**（★差异化交互） | 结果卡内一条横向色带：绿/黄/红 = 行业基准区间（如 food cost 28-35% 绿），用户位置用指针标出 + 文字判定（"You're in the healthy range" / "11 points above typical — here's what that costs you per year"）。标尺下方一行小字 "Industry range: 28-35% (US full-service)" |
| 7 | **一句话诊断 + 下一步路由** | 结果不是裸数字，是判断。诊断驱动 3.6 节的"下一步"区内容（变现引擎，见流程 C） |
| 8 | **状态持久化** | ① localStorage 按工具 slug 自动存草稿，回访还原；② 全部输入序列化进 URL query（`?tips=847.5&s=70&b=20&bar=10`），`Copy link` 生成分享链接，打开即还原计算——免费实现"保存/分享"，零后端 |
| 9 | **Email me this** | 动作条内 inline 展开（**不用弹窗**）：邮箱输入 → 提交 → 成功态"Check your inbox"。邮件内容 = 结果摘要 + 报告链接 + 一条行业 tips + 一个 soft affiliate 位。轻量防刷：同邮箱 10 分钟 1 次 + honeypot |
| 10 | **Print / PDF** | `@media print` 样式：隐藏输入 chrome 和导航，输出一张干净 one-pager（品牌头 + 输入参数表 + 结果 + 日期）。Dana 现场给客户看的就这张纸。页脚固定 "Saved with Main Street Toolbox — create a free account"（Pro 去水印+自定义 logo） |
| 11 | **Save** | 免登录：存 localStorage，toast 提示 "Saved on this device"；第 4 次触发付费墙对话（流程 B）。登录用户存云端 |
| 12 | **错误/空状态** | 无效输入：字段级红框+行内提示，结果卡变灰显示 "Fix the highlighted fields"。**永远不弹 alert** |
| 13 | **键盘流** | 输入框间 Tab 顺序 = 视觉顺序；Enter 不触发提交（无 form）；结果卡有 `tabindex` 可聚焦 |
| 14 | **性能红线** | 工具计算 JS 随页内联或 idle 时 hydration，每页交互 JS < 60KB；结果卡固定高度预留（CLS=0）；LCP < 1.5s（4G） |
| 15 | **无障碍** | label 全绑定；触控目标 ≥44px；对比度 AA；focus 可见。这类用户年龄层偏高（Pam 48 岁），字号基准 16px，结果大数字 40px+ |

**Below the fold 内容区**（SEO 承重，每页 400-700 词）：
- **What this number means**：把结果翻译成人话（"food cost 31% means for every $1 that comes in, 31¢ goes to ingredients"）+ 内置行业基准表（这是内容护城河，标注来源）
- **How to use this calculator**：3 步图文
- **FAQ**：4-6 个真实问题，FAQPage schema
- **Next steps（变现位）**：见 3.6
- **Related tools**：同行业 4-6 个，文字链
- **Sources/data note**：基准数据出处（可信度+外链诱饵）

### 3.3 行业枢纽页（如 /restaurant）

- H1: "Free Restaurant Calculators & Tools"
- 工具目录卡列表：每个工具 = 名称 + 一句话 + "used this week" 数字
- 行业 quick answers 区（页面下部 300 词 SEO 文本："What is a good food cost percentage?" 风格问答，直连对应工具）
- 该行业 1 个 partner 推荐位（如 Toast），标注 "Partner"——枢纽页流量泛，affiliate 位放这里比工具页更自然

### 3.4 报告页 /r/<id>

保存的计算生成的独立页：标题（菜名/客户名可编辑）、参数表、结果、基准标尺、创建日期。可分享（公开链接）可打印。
- 免费用户：保留最近 3 份
- Pro：无限 + PDF 导出去水印 + 加自己 logo
- 这是 "结果带得走" 的落点，也是付费墙实体

### 3.5 定价页 /pricing + 免费墙分界

顶部一句承诺："**Every calculator is free forever. Pro just helps you keep your work.**"

| 能力 | Free | Pro $9/mo 或 $79/yr |
|---|---|---|
| 全部工具，无限次使用 | ✅ | ✅ |
| 结果保存 | 本机，最近 3 份 | 云端，无限 + 历史对比 |
| 打印/PDF 报告 | 带品牌页脚 | 无水印 + 自定义 logo |
| 客户档案（每客户报价历史）| ❌ | ✅（cleaning/lawn 刚需） |
| 完整行业基准数据表 | 摘要 | 完整 |

**付费墙原则**：工具计算本身永不设限（SEO 护城河+信任来源）。所有墙都砌在"带走和复用"层。

### 3.6 "下一步"区（变现引擎，所有工具页共用组件）

根据**诊断结果**路由内容，规则表驱动（不是猜）：

| 诊断 | 展示 |
|---|---|
| 健康（绿区） | 相关工具互链 + "Subscribe to Main Street Numbers" 邮件周报 |
| 警告（黄区） | 同类工具深度计算入口（food cost 高 → menu pricing calculator："see what your new price should be"） |
| 危险（红区，连续触发） | 行业软件 partner 位："Food cost this high usually means spreadsheets stopped keeping up. See how Toast handles this automatically →" + disclosure 标注 |
| 特定场景 | 精选 guide 文链 |

Partner 位**只在红区 + 枢纽页**出现。绿区用户面前不放广告位——保信任。

### 3.7 账号体系（极简）

- **Magic link only**：输邮箱 → 收登录链接。辅以 Google 一键登录。**不做密码**（Pam 不会设也记不住）。
- 账号中心三件事：Saved results 列表、订阅管理（Stripe portal）、Pro 客户档案。
- 未登录状态完全可用——账号只在"保存/同步/客户档案"时出现。

## 4. 业务流程

### 流程 A：主漏斗（游客 → 使用 → 邮箱捕获）

```
Google "tip out calculator"
   → 落地工具页（无 cookie 横幅、无弹窗）
   → 改预填数字，结果实时更新
   → 点 [Email me this] → inline 输邮箱
   → 收到：结果摘要 + 报告链接 + 1 条行业 tips + 1 个 soft affiliate
   → 进入 "Main Street Numbers" 周报 nurture
      （每周 1 封：1 个行业指标 + 1 个工具 + 1 个 partner offer，随时退订）
```
转化目标基线：result_seen → email_captured ≥ 5%。

### 流程 B：免费 → Pro 升级（收敛点设计）

不硬堵，在"重复使用"的时刻出现：

| 触发时刻 | 文案方向 |
|---|---|
| 第 4 次 Save | "You've got 3 saved results. Upgrade to keep them all — or delete one." |
| 首个客户档案后建第 2 个（Pro 行业功能） | "Looks like you're working with more than one client. Pro keeps every quote in one place." |
| 打印报告点击"去水印" | 直接展示 Pro 前后对比（水印页 vs 自己 logo 的报价单） |
| 邮件周报 | 每月 1 次 soft CTA |

价格锚定：$9/mo 一杯咖啡钱 vs "one bad tip-out split pays for a year"。

### 流程 C：Affiliate 转化（合规优先）

```
工具诊断出红区结果（如 food cost 41%）
   → "Next steps" 出现行业 partner 位（Toast/Gusto/Homebase，按行业路由）
   → 点击 → /best/restaurant-pos 对比页（真实评测，不软文）
   → affiliate 链接 → 转化
```
- 全站 FTC 合规：affiliate 链接带 `rel="sponsored"`，页脚固定 Affiliate Disclosure 页，partner 位标注 "Partner"
- 红线：不给绿区用户推 partner（保工具可信度）；对比页必须真实测试过，不写没用过的产品

### 流程 D：SEO 内容飞轮

```
工具页(交易意图, 免疫 AI Overviews) ←互链→ 指南长文(信息意图, 吃剩余点击)
每月发布 1 份行业基准报告（"We analyzed 500 menu prices"）
   → 可被引用的数据 → 自然外链 → 全站权重上升
```

## 6. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | **Astro + vanilla TS**，纯静态 | 团队熟悉；计算全在客户端 → 快、便宜、稳、零 API 攻击面 |
| 计算 | 每工具一个纯函数模块（输入→输出+诊断），可单测 | 逻辑与 UI 分离，扩行业时模板化复制 |
| 状态 | localStorage（草稿）+ URL query 序列化（分享/保存） | 免登录态零后端 |
| 账号/存储 | Supabase（magic link auth + PG） | 后端从零起步最快；仅 Save/报告/客户档案用 |
| 支付 | Stripe Checkout + Customer Portal | 不自建订阅逻辑 |
| 邮件 | Resend（结果邮件 + 周报） | 送达率好，模板简单 |
| 分析 | **Plausible（cookieless）** | 无 cookie 横幅（转化杀手）；**不要复用矩阵的 GA4 ID，账号体系隔离** |
| 部署 | Cloudflare Pages | 成本≈0，全球 CDN |
| SEO | WebApplication + FAQPage + HowTo schema；每页 canonical；工具页 <title> = "{Tool} — Free {industry} tool" | |
| 埋点漏斗 | tool_page_view → first_input → result_seen → save_click → email_captured → upgrade_view → subscribed | 北极星：周 email_captured；之后 MRR |

**与矩阵的关系**：完全独立 repo/域名/账号体系/分析账号。不用 `new-site.sh`（那是 whataicando 子域骨架）。唯一共享：部署脚本习惯、Astro 经验。**在 AdSense 账号解除限制前，本站不接任何 Google 广告代码**——这也是"No ads"信任卖点的来源。

## 9. v1.1 增补（2026-09-05 定稿）

### 9.1 三层架构（终局：从工具站到数据链）

> 战略定位：本站是 SaaSMatrix（真 SaaS 方向）的第一块拼图，不是广告矩阵站。终局链路：**免费工具带流量 → 账户留人 → 数据链收钱**（链路需求已被 Recipe Cost Calculator 验证：$24-107/月、2 万+客户）。

| 层 | 是什么 | 状态 |
|---|---|---|
| **L1 工具面** | 纯静态、零门控、客户端计算的免费工具（§3 全部设计不变） | M1 起建，**SEO 护城河，永不让渡** |
| **L2 账户面** | magic link 账户：收藏工具、保存结果、客户档案、订阅（/app 路由下） | M2-M3 按原计划 |
| **L3 数据链** | Menu Costing Chain：采购→使用→成本分摊→收益→净利润的**预制模板链** | **不立项开发**，由 §9.3 触发规则决定 |

**两条铁律**：① L3 是预制模板链，**永远不做用户自由搭建的 workflow builder**（用户画像否决节点编辑器）；② L1 永远零门控，账户/链/服务不织进工具页。

### 9.2 Concierge 定制服务（L3 的人力先行版）

不写一行链代码，**人就是 workflow 引擎**：

- 形态："Done-for-you setup"——客户交进货单/菜单照片，我们交付配好的计算链 + 可打印月度报告模板
- 定价：$99 起步（founding price）一次性 setup + 要求 Pro 订阅；**每月 5 个名额**（定价与限额即需求过滤器）
- 入口只有三处：/services 页、Pro 定价页、邮件周报；**工具页永不出现**
- 线索用结构化 intake 表单（有什么数据/要哪条链/何时要），异步邮件交付，**不承诺电话会议**
- 交付方式：初期用现有工具+手工计算，不写新代码；**每个定制交付沉淀一份模板候选，第 5 个相似需求出现即产品化为预制链**
- 生产力协同：定制单增多后，矩阵 ai-api 作为*内部*工具解析小票/菜单照片 → 结构化条目（服务我们自己，不暴露给终端用户）
