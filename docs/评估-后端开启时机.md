## 一、分层框架

### Tier 0 — 使用统计（Worker + D1）｜**现在就开**
- 性质：这是**测量不是服务**——不增加面向用户的面，无安全面扩大，免费额度 100k 写/天
- 解锁：per-tool 真实使用数据（GA 只有 pageview；我们最缺"哪个工具被真用"的信号，选题全靠猜）
- 成本：`wrangler d1 create mst-stats` → 填 database_id → deploy → 站点 env 加 `PUBLIC_STATS_API`，合计 10 分钟
- **触发条件：现在。** 唯一阻塞：Cloudflare 账号操作（wrangler login 状态待查）

### Tier 1 — 账号系统（共享 Supabase）｜三条件触发，满足两条即启动准备
1. **留存信号**：09-22 中检（周自然点击 ≥10）达成，且 4 周趋势为周 UV ≥300 或回访率 ≥15%
2. **需求信号**：≥3 条真实用户反馈要"保存/跨设备/导出"（来源：Reddit 评论、feedback 表单、外联来信）
3. **商业信号**：准备启动 Pro 变现（Ko-fi → Pro 订阅）——Pro 的核心卖点（云保存、无限文档）就是后端
- 实现路线（M2 既定）：**租不自建**——共享 Supabase 项目，magic link only，saved_items 单表起步；密钥不出前端构建
- 成本：Supabase 免费层（500MB DB / 50k MAU）足够 12 个月+；工程量 1-2 周
- 为什么不用 VPS/ai-api：架构文档已定 SaaS Core 租 Supabase；把站点业务数据放上矩阵共享后端会耦合两个独立资产的运维

### Tier 2 — 工具箱主页（聚合分享页：价目表+计算器+名片 QR）｜跟在 Tier 1 后
- 前置：Tier 1 已上线（用户数据在服务端，分享页才有好体验）
- 触发：≥3 条"想把结果分享给客户"的用户反馈
- 这是"名片/主页"方向唯一被保留的形态（见 docs/评估-digital-card-profile-booking.md）

## 二、反向清单（出现任一，继续推迟 Tier 1）

- 09-22 中检未达（周自然点击 <10）→ 后端没有服务对象，先解决流量
- 候选池还有 ≥2 个全闸工具未做（当前：pour cost、aeration、painting 研究中）→ 工程时数应继续投向 SEO 内容资产
- 零用户提出保存类需求 → 账号系统是伪需求，永远不用为做而做

## 四、一句话原则

**后端跟随留存，不领先留存。** 站点当前的全部增长引擎是 SEO 内容资产（零后端、零成本、断网可算），后端的每一段都必须由真实用户行为触发，而不是由"我们能做"触发。
